## 1. 获取内核源码

### 方式一：git

直接 clone kernel.org 速度会很慢甚至超时，用镜像快很多：
```bash
# 国内镜像（清华，速度快）
git clone https://mirrors.tuna.tsinghua.edu.cn/git/linux.git

# 只 clone 5.15 分支，不拉全部历史，体积小很多
git clone --branch v5.15 --depth 1 \
  https://mirrors.tuna.tsinghua.edu.cn/git/linux.git
```

+ `--depth 1`（浅克隆）: 表示只取最新一层快照，大幅减小体积、加快下
载
    > 代价：没有完整 git 历史，不能 `git log` 查看历史提交记录，也不能切换到其他分支或版本。
    {: .prompt-info }

+ 补充：如果之后想看完整历史，可以补全：
```bash
git fetch --unshallow
```
但对编译内核来说，浅克隆就够了，没必要补全。

### 方式二：压缩包（推荐）

内核源代码 tar 压缩包：[kernel.org 源码目录](https://www.kernel.org/pub/linux/kernel/)
> 进入后按版本（如 `v5.x/`）找到对应的 `.tar.xz` 等压缩包下载。
{: .prompt-info }

+ linux-x.y.z.tar.bz2
```bash
tar xvjf linux-x.y.z.tar.bz2
```

+ linux-x.y.z.tar.gz
```bash
tar xvzf linux-x.y.z.tar.gz
```

+ linux-x.y.z.tar.xz
```bash
tar xvJf linux-x.y.z.tar.xz
``` 

**补充**：
+ 现代 tar 可以自动识别压缩格式，所以可以直接省略 j/z/J：
```bash
tar xvf linux-x.y.z.tar.bz2
```
+ `v` 代表 verbose，显示解压过程，省略后不会显示解压过程。
+ `-C <target_dir>` 代表解压到指定目录，省略后默认解压到当前目录。

## 2. 编译内核

### 2.1 配置内核
在编译内核之前，首先必须配置内核；将自己需要的特定功能和驱动程序编译进内核；

配置的结果最终保存在内核源码根目录下的 **`.config`** 文件中，它是内核编译的核心配置文件。

+ `.config` 是一个纯文本文件（以 `.` 开头，默认隐藏），里面是成千上万条形如 `CONFIG_XXX` 的配置项，每一项决定某个功能或驱动是否编译、以何种方式编译。
+ 每个配置项有三种状态：

```bash
CONFIG_EXT4_FS=y                 # y：直接编译进内核镜像（built-in）
CONFIG_USB_STORAGE=m             # m：编译成可加载模块（.ko），需要时再加载
# CONFIG_DEBUG_INFO is not set   # 未设置：不编译该功能
```

+ 这个文件通常通过 `make menuconfig`、`make defconfig`、`make oldconfig` 等命令生成和修改（下文介绍）。

> 生成 `.config` 后若还想修改，除了 `make xxxconfig` 命令，也可以直接用编辑器改 `.config` 后编译；或用源码自带的 `scripts/config` 脚本工具修改（如 `scripts/config --disable DEBUG_INFO`），改完执行 `make olddefconfig` 同步即可。
{: .prompt-tip }

> `.config` 决定了最终内核"长什么样"：包含哪些驱动、支持哪些文件系统、开启哪些特性。同一份源码，不同的 `.config` 会编译出功能差异很大的内核。
{: .prompt-info }

**以下方式就情况则一使用：**

#### 2.1.1 生成默认配置

基于默认的配置为你设备的体系结构创建一个配置：
```bash
# 进入内核源码目录
cd linux-x.y.z
make defconfig
```


<details markdown="1">
<summary>📖 展开：make defconfig 的工作原理</summary>

**默认配置从哪来？**

`make defconfig` 并非凭空生成配置，而是读取内核源码中**预先定义好的 defconfig 文件**，路径由架构决定：

| 架构 | 默认 defconfig 文件 |
| --- | --- |
| x86 (64位) | `arch/x86/configs/x86_64_defconfig` |
| x86 (32位) | `arch/x86/configs/i386_defconfig` |
| ARM64 | `arch/arm64/configs/defconfig` |
| ARM | `arch/arm/configs/xxx_defconfig`（众多板级配置） |

具体用哪个，由 `arch/<arch>/Makefile` 中的 `KBUILD_DEFCONFIG` 变量决定（如 x86_64 对应 `x86_64_defconfig`）。

**底层做了什么？**

最终调用 `scripts/kconfig/conf` 程序，以 `--defconfig=arch/<arch>/configs/xxx_defconfig` 读取该文件，再结合整棵 Kconfig 规则树，生成完整的 `.config`。

**几个关键认识：**

+ defconfig 文件由**内核 / 板级维护者精心挑选**并提交到源码树，目标是提供一个"最小但能启动"的基础配置，供用户在此基础上定制。
+ defconfig 只包含**显式设置的选项**，并非完整 `.config`；未列出的选项取 Kconfig 中定义的 `default` 值。
+ `make savedefconfig` 可反过来从当前 `.config` 生成一份精简的 defconfig 文件。

</details>


#### 2.1.2 继承原有配置（推荐）
> 给 Ubuntu/Debian 等发行版更换内核的场景非常合适；

1. 解压内核源码，并进入源码目录

       # 进入内核源码目录
       cd linux-x.y.z

2. 导入你当前系统正在运行的内核配置：

   Ubuntu/Debian 系统通常会把内核配置文件放在 /boot 目录下，例如：

       # uname -r -> 当前内核版本
       cp /boot/config-$(uname -r) .config

   这一步就是“用上系统当前的配置”。

3. 根据系统当前配置，生成新的配置

   + 执行 `make oldconfig`:

         make oldconfig

     **作用**：

     + 读取复制过来的 .config;
     + 检查内核源码的 Kconfig;
     + 如果新内核有新配置项，它会一个一个询问你要怎么选（y、n、m）；
     + 没有新增项就什么也不问，直接更新 .config。

   + 如果你不想一个个手动输入新选项，可以:

         make olddefconfig

     **作用**：

     + 读取当前目录的 .config
     + 对照内核源码里的 Kconfig（所有可配置项的定义）
     + .config 中已设置过的选项 → 原样保留，不动
     + 新出现/缺失的选项 → 自动用默认值填上（不再交互式询问）
     + 写回一个完整、同步好的 .config

#### 2.1.3 交互式配置
```bash
make menuconfig
```

##### **帮助示例**
比如你选中了 CONFIG_SMP 选项后按 h，会显示类似这样的内容：
```
Symbol: SMP [=y]
Type  : bool
Prompt: Symmetric multi-processing support
  Location:
    -> General setup
  Defined at init/Kconfig:88
  Depends on: ...
  Selects: ...
```
+ Symbol: 配置符号名
+ Type: 配置类型（bool/tristate/int/string 等）
+ Prompt: 配置项的描述
+ Location: 配置项在 Kconfig 树中的位置
+ Defined at: 配置项定义的 Kconfig 文件和行号
+ Depends on: 依赖关系（哪些选项必须启用才能启用该选项）
+ Selects: 选择关系（启用该选项会自动启用哪些选项）
{: .text-muted}

**常用快捷键**

| 按键 | 功能 |
| --- | --- |
| `h` | 查看当前选项帮助 |
| `?` | 显示主帮助菜单 |
| `/` | 搜索配置项（输入关键词，如 `EXT4`） |
| `y` / `n` / `m` | 设置当前选项为 是/否/模块 |
| `Enter` | 进入子菜单 / 切换 bool 选项 |
| `Esc` | 返回上级菜单 |
| `Space` | 切换选项状态 |

搜索功能（`/`）特别实用，因为选项数量庞大，直接找几乎不可能。比如输入 GDB_SCRIPTS，它会告诉你这个选项在哪里、是否可选、依赖什么。

## 3. 编译

.config 配置生成后，编译：
```bash
make -j$(nproc)
```
> `$(nproc)` 值即 逻辑核心数，也即 "物理核心数 x 每核线程数"；
{: .prompt-info }
